## 중첩된 데이터와 함수형 도구 활용

### 요약

- 중첩된 데이터를 다룰 때 함수형 프로그래밍 기법 활용
- 재귀 함수의 원리와 안전한 사용법 이해
- 타임라인 다이어그램을 통해 코드 실행 순서 분석
- 동시성 문제 해결을 위한 원칙 정리

### 필드명을 명시적으로 만들기

- 암묵적 인자를 제거하고 함수 본문을 콜백으로 리팩토링
- 객체 변경을 `update` 함수로 일관되게 처리
- 중첩된 객체에서도 올바르게 동작하는지 검토 필요

### 중첩된 `update` 문제 해결

- 중첩된 데이터를 수정할 때 `update` 내부에 `update`를 중첩하여 사용
- 하지만 이 방법은 데이터 구조가 깊어질수록 비효율적
- 이를 해결하기 위해 `nestedUpdate` 함수 도출

```js
function nestedUpdate(object, keys, modify) {
  if (keys.length === 0) return modify(object);
  const [key1, ...restOfKeys] = keys;
  return update(object, key1, (value1) =>
    nestedUpdate(value1, restOfKeys, modify),
  );
}
```

### 안전한 재귀 사용법

- 무한 재귀 방지 원칙
  - 종료 조건 명확히 설정
  - 최소 하나의 재귀 호출 유지
  - 종료 조건으로 점진적으로 접근
- 재귀 함수가 적합한 이유
  - 중첩된 데이터의 깊은 레벨까지 접근 후 수정하면서 반환 가능

## 타임라인 다이어그램과 동시성 문제

### 버그 해결을 위한 타임라인 분석

- 책에서는 장바구니 합계 금액과 실제 결제 금액 불일치 문제 발생
- 빠르게 클릭하면 동시성 문제가 발생할 가능성 존재
- 타임라인 다이어그램을 활용하여 문제 원인 분석

### 타임라인 다이어그램 개념

- 액션을 순서대로 정리하여 실행 흐름을 시각적으로 표현
- 두 액션이 순차적이면 같은 타임라인, 동시 실행되거나 순서가 보장되지 않으면 다른 타임라인
- 일반적으로 스레드, 프로세스, 비동기 콜백이 다른 타임라인을 형성

### 타임라인 관련 원칙

- 타임라인 개수가 적을수록 코드 이해가 쉬움
- 짧은 타임라인이 유지보수하기 용이함
- 공유 자원이 적을수록 안정적인 코드 작성 가능
- 공유 자원이 많다면 조율 메커니즘이 필요
- 시간 요소를 일급 값(first-class citizen)으로 다루기

### 자원 공유 문제 해결

- 동시성 문제를 방지하기 위해 큐 사용
  - 큐: FIFO(First-In-First-Out) 방식으로 실행 순서 보장
  - 타임라인을 조율하는 동시성 기본형(concurrency primitive)
- 큐를 함수형으로 구현하여 재사용성 확보

## 결론

- 중첩된 데이터를 다룰 때 재귀 함수 활용이 효과적
- 타임라인 다이어그램을 통해 코드 실행 순서 분석 및 동시성 문제 해결
- 동시성 처리를 위해 큐 등 동시성 기본형을 도입하여 코드 안정성 향상
